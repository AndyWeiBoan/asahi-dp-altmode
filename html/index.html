§1現在的狀態

最後更新 2026-09-24 凌晨
kernel 7.1.13-fairydust+（fairydust 分支 + patch 0001 + #622）
官方 7.1.13-402.asahi 留在 GRUB 當退路，5 秒選單
冷插外接螢幕 ✅ 可用 —— 開機前插在左側靠前那個 USB-C 孔就有畫面
熱插拔 ❌ 畫面回不來。至少不再卡住整台電腦（#622 的功勞）
臨時解法：wlr-randr --output DP-1 --off && sleep 1 && wlr-randr --output DP-1 --on —— 目前也救不回來，真正要修得動 driver
Studio Display ⬜ 還沒測過。到目前為止全部是用 MSI MAG161V 做的
迭代迴圈 ✅ 改 C → 約 40 秒增量編譯 → 裝模組 → 重開機測
卡住的點在合成器，不在 kernel。 拔線時 DCP 吞掉一張 page flip 且從不回報完成，aquamarine 之後就拒絕所有 commit （Cannot commit when a page-flip is awaiting）。 完整的推理在 手冊 §3。

§2下一步

  1. 一起寫一份學習計畫 —— 不是單方面寫完丟過來的那種
  2. 把兩個 patch 逐行看懂：0001（內建 HDMI resume，11 行，暖身）和 #622（兩塊，42 行）。 白話版已經在 手冊 §3，但要真的一行一行看過
  3. 討論熱插拔。重點不只是修好，是搞懂那些探測手段各自在看哪一層 —— 對照表在 手冊 §2
  4. 然後才動 iomfb.c。程式自己寫

分工：程式自己寫，Claude 負責解釋機制、指出該看哪裡、幫忙讀結果、review。 安裝設定那類純操作讓它直接做完。

兩分鐘就能做、但還沒做的事：把 Studio Display 插上去冷開機一次。 正主到現在都還沒上場，很可能會看到 acking unhandled call 20 —— 那是完全不同的一條線（斷點 2）。先知道它長什麼樣，排優先順序會有依據。

§3這裡有什麼

MacBook Pro 14" M1 Pro（MacBookPro18,3，t600x）+ Fedora Asahi Remix + Hyprland， 把外接螢幕點亮。表面上是修螢幕，真正想補的是硬體到 kernel 之間那段空白。

手冊 操作、診斷、這台機器的硬事實、踩過的坑、開機鏈、名詞表。卡住的時候來這裡查。 日誌 每次動手記一筆：做了什麼、量到什麼、哪裡做錯。只寫不太讀，但回頭找線索時很有用。 計畫 大方向、兩個斷點、六階段學習階梯、遠期的 m1n1 雙機 trace、材料清單。一個月看一次。
